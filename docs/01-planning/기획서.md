# 심이베 캘린더 프로젝트 기획서 (v1.0)

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 심이베 캘린더 |
| 형태 | 모바일 앱 (Android 우선, 이후 iOS) |
| 한 줄 소개 | 연결된 사람에게 일정을 골라 공유하고, 내 기준의 분류로 정리해 보는 일정관리 앱 |
| 최종 목표 | 플레이스토어와 앱스토어 정식 출시 |
| 1차 목표 | 2026년 11월 말까지 안드로이드에서 핵심 기능이 동작하는 첫 버전(1.0) 개발 완료 |

## 2. 배경과 문제 정의

- 기존 캘린더 앱은 **캘린더 단위로 공유**하는 경우가 많아서, 특정 일정만 특정 사람과 나누기 불편하다.
- 같은 일정을 사람마다 따로 등록하면 **시간이나 내용이 어긋난다.**
- 한 사람의 일정이 직장, 교회, 가족 등 여러 영역에 섞여 있어서 **영역별로 나눠 보기 어렵다.**
- 같은 일정이라도 사람마다 의미가 다르다. A에게는 "직장" 일정이 B에게는 "가족" 일정일 수 있다.

## 3. 대상 사용자

- 특정 집단에 한정하지 않는 범용 사용자
- 주요 사용 상황: 직장 동료, 교회 공동체, 가족 등 여러 관계 속에서 일정을 함께 맞춰야 하는 사람

## 4. 핵심 컨셉

### 4.1 계정 연결

- 가입할 때 정한 **고유 아이디로 상대를 검색**해서 연결을 요청하고, **상대가 수락하면 연결**된다.
- 이메일은 로그인에만 쓰이고 다른 사용자에게 공개되지 않는다.
- 연결된 사람은 서로 일정을 공유할 수 있는 신뢰 관계가 된다.
- 연결을 해제하면 **앞으로 새 일정을 공유할 수 없게** 되며, 이미 함께 참여 중인 일정은 그대로 유지된다.

### 4.2 일정 단위 공유

- 일정을 등록하거나 수정할 때 **연결된 사람 중 공유할 대상을 고른다.**
- 공유된 일정은 상대방 달력에 **승인 없이 바로 등록**된다.
- 원본 일정은 하나이며, 변경 내용은 **모든 참여자에게 즉시 반영**된다.

### 4.3 참여자 규칙

**모든 참여자의 권한은 같다.** 일정을 만든 사람에게도 별도 권한은 없다.

| 행동 | 규칙 |
|---|---|
| 일정 수정 | 참여자 누구나 가능 |
| 참여자 추가 | 참여자 누구나 자기와 연결된 사람을 추가 가능 |
| 참여자 제외 | 불가능. 각자 스스로만 빠질 수 있음 |
| 일정 삭제 | 자기 달력에서만 빠짐. 참여자가 모두 빠지면 일정이 실제로 삭제됨 |

### 4.4 개인별 분류

- 사용자는 "직장", "교회", "가족"처럼 **자신만의 분류**를 만들 수 있다.
- 일정에 분류를 지정하고, 원하는 분류만 골라서 볼 수 있다.
- 분류는 **사람마다 따로** 관리된다. 공유받은 일정은 처음에 "공유받은 일정" 분류로 들어오고, 받은 사람이 자기 분류로 바꿀 수 있다.

## 5. 주요 기능

### 5.1 버전 1.0 (1개월 목표)

| 구분 | 기능 |
|---|---|
| 회원 | 이메일과 비밀번호로 회원가입(고유 아이디 설정 포함)·로그인·로그아웃, 비밀번호 재설정, 회원 탈퇴 |
| 연결 | 고유 아이디로 사용자 검색, 연결 요청·수락·거절, 연결 목록, 연결 해제 |
| 일정 | 월간 달력 보기, 일정 등록·수정, 내 달력에서 빼기 |
| 공유 | 연결된 사람 선택해서 공유, 참여자 추가, 참여자 목록 보기, 실시간 반영 |
| 분류 | 분류 생성·수정·삭제, 색상 지정, 분류별 필터 보기 |
| 반복 | 매일, 매주, 매월 반복 (수정과 삭제는 전체 일정 기준) |
| 알림 | 일정 시작 전 알림, 공유받거나 공유 일정이 수정됐을 때 알림 |

### 5.2 버전 1.1 이후

- 소셜 로그인 (카카오, 네이버, 구글, 애플)
- 반복 일정의 "이번 일정만 수정"
- 주간, 일간 보기
- 수정 이력 (누가 언제 무엇을 바꿨는지)
- 일정 댓글, 장소와 지도
- 외부 캘린더 불러오기

## 6. 차별점

| 비교 항목 | 기존 캘린더 앱 | 심이베 캘린더 |
|---|---|---|
| 공유 단위 | 캘린더 전체 또는 이메일 초대 | 연결된 사람에게 일정 단위로 바로 공유 |
| 공유 절차 | 초대하고 상대가 수락해야 함 | 연결만 되어 있으면 바로 등록 |
| 권한 구조 | 만든 사람(주최자) 중심 | 모든 참여자가 같은 권한 |
| 분류 | 공유 캘린더의 분류를 따름 | 같은 일정도 사람마다 자기 분류로 관리 |

## 7. 기술 스택

| 영역 | 기술 |
|---|---|
| 개발 도구 | Android Studio (Flutter, Dart 플러그인 설치) |
| 앱 | Flutter, Dart |
| 상태 관리 | Riverpod |
| 달력 UI | `table_calendar` |
| 백엔드 | Supabase (인증, PostgreSQL, Realtime, Edge Functions), `supabase_flutter` 패키지 |
| 푸시 알림 | Firebase Cloud Messaging (`firebase_messaging`) |
| 일정 시작 전 알림 | `flutter_local_notifications` |
| 테스트 기기 | 안드로이드 에뮬레이터, 안드로이드 실기기 |

## 8. 단계별 일정

### 8.1 1단계: 첫 버전 개발 (4주, ~11월 말)

| 주차 | 내용 |
|---|---|
| 1주차 | 요구사항 정의, 화면 설계, ERD, 개발환경 구축, 회원가입·로그인 |
| 2주차 | 달력 화면, 일정 등록·수정·빼기, 분류 |
| 3주차 | 계정 연결, 일정 공유, 참여자 관리, 실시간 반영, 반복 일정 |
| 4주차 | 알림, 기능 테스트, 버그 수정 |

**완료 기준:** 안드로이드 기기 2대 이상에서 회원가입부터 연결, 공유, 알림까지 전체 흐름이 동작한다.

### 8.2 2단계: 베타 테스트 (기간 미정)

- 지인 대상으로 Google Play 내부 테스트 배포
- 피드백을 받아 개선

### 8.3 3단계: 정식 출시 준비 (기간 미정)

- iOS 빌드와 테스트 (Mac 환경 필요)
- 개인정보처리방침, 스토어 등록 자료 준비
- 플레이스토어, 앱스토어 심사 제출

## 9. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 누구나 수정할 수 있어서 의도치 않은 변경이 생길 수 있음 | 수정 알림 발송, 1.1에서 수정 이력 추가 |
| 승인 없이 바로 등록돼서 원치 않는 일정이 쌓일 수 있음 | 연결 수락 단계에서 신뢰 확보, 연결 해제와 "내 달력에서 빼기" 제공 |
| 참여자가 추가한 사람을 통해, 나와 연결되지 않은 사람도 같은 일정에 참여할 수 있음 | 일정 상세에 참여자 목록을 표시해서 누가 보고 있는지 알 수 있게 함 |
| 참여자가 모두 빠진 일정이 데이터로 남을 수 있음 | 마지막 참여자가 빠지면 서버에서 자동 삭제 |
| iOS 개발에 Mac이 필요함 | 1.0은 안드로이드로 검증, iOS는 출시 준비 단계에서 Mac이나 클라우드 빌드 서비스(Codemagic 등) 이용 |
| Flutter와 Dart가 처음일 경우 학습 시간 필요 | 1주차에 기본 화면 구성과 상태 관리 학습 시간 확보 |
| 1개월 일정 지연 | 1.0 범위를 고정하고 추가 기능은 1.1로 미룸 |
