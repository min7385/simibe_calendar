# 심이베 캘린더 요구사항 정의서 (v1.0)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 문서 목적 | 심이베 캘린더 1.0의 기능 및 비기능 요구사항 정의 |
| 대상 버전 | 1.0 (안드로이드) |
| 참고 문서 | `docs/01-planning/기획서.md` |

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 고유 아이디 | 가입할 때 정하는 사용자 식별 아이디. 연결 요청 검색에 사용되며 변경할 수 없다. |
| 이름 | 다른 사용자에게 보이는 표시 이름(닉네임) |
| 연결 | 연결 요청을 상대가 수락해서 맺어진 관계. 연결된 사람끼리 일정을 공유할 수 있다. |
| 참여자 | 하나의 일정을 함께 공유하고 있는 사용자. 모든 참여자의 권한은 같다. |
| 내 달력에서 빼기 | 일정에서 자신만 빠지는 동작. 다른 참여자의 일정은 유지된다. |
| 분류 | 사용자가 개인적으로 일정을 나누는 기준. 사람마다 따로 관리된다. |
| 시작형 일정 | 시작 시간만 있는 일정 |
| 마감형 일정 | 종료 시간만 있는 일정 |
| 기간형 일정 | 시작 시간과 종료 시간이 모두 있는 일정 |
| 하루 종일 일정 | 시간 없이 날짜만 있는 일정 |

## 3. 기능 요구사항

### 3.1 회원 (AUTH)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-AUTH-001 | 회원가입 | 이메일, 비밀번호, 고유 아이디, 이름을 입력해서 가입한다. | 상 |
| REQ-AUTH-002 | 이메일 인증 | 가입 후 메일로 받은 인증 링크를 눌러야 로그인할 수 있다. | 상 |
| REQ-AUTH-003 | 고유 아이디 규칙 | 8자 이상, 영문과 숫자를 모두 포함해야 한다(비밀번호 규칙 NFR-005와 동일). | 상 |
| REQ-AUTH-004 | 고유 아이디 중복 확인 | 이미 사용 중인 고유 아이디로는 가입할 수 없다. | 상 |
| REQ-AUTH-005 | 로그인 | 이메일과 비밀번호로 로그인한다. 로그인 상태는 앱을 다시 열어도 유지된다. | 상 |
| REQ-AUTH-006 | 로그아웃 | 로그아웃하면 이 기기에서 해당 계정의 알림을 받지 않는다. | 상 |
| REQ-AUTH-007 | 비밀번호 재설정 | 가입한 이메일로 재설정 링크를 받아 비밀번호를 바꾼다. | 상 |
| REQ-AUTH-008 | 프로필 수정 | 이름을 수정할 수 있다. 고유 아이디와 이메일은 변경할 수 없다. | 중 |
| REQ-AUTH-009 | 회원 탈퇴 | 탈퇴하면 계정, 분류, 연결 정보가 삭제되고, 참여했던 모든 일정에서 빠진다. 다른 참여자의 일정은 유지된다. | 상 |

### 3.2 연결 (CONN)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-CONN-001 | 사용자 검색 | 고유 아이디를 정확히 입력해서 사용자를 찾는다. 검색 결과에는 고유 아이디와 이름만 보인다. | 상 |
| REQ-CONN-002 | 연결 요청 | 검색한 사용자에게 연결을 요청한다. 이미 연결됐거나 요청 대기 중이면 요청할 수 없다. | 상 |
| REQ-CONN-003 | 요청 수락·거절 | 받은 요청을 수락하면 연결되고, 거절하면 요청이 사라진다. 거절한 사실은 상대에게 알리지 않는다. | 상 |
| REQ-CONN-004 | 요청 취소 | 보낸 요청이 수락되기 전에 취소할 수 있다. | 중 |
| REQ-CONN-005 | 연결 목록 | 연결된 사람, 받은 요청, 보낸 요청 목록을 볼 수 있다. | 상 |
| REQ-CONN-006 | 연결 해제 | 연결을 해제하면 앞으로 서로 새 일정을 공유할 수 없다. 이미 함께 참여 중인 일정은 유지된다. 상대에게 알리지 않는다. | 상 |

### 3.3 일정 (EVENT)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-EVENT-001 | 일정 등록 | 아래 입력 항목으로 일정을 등록한다. | 상 |
| REQ-EVENT-002 | 입력 항목 | 제목(필수), 시간(3.4 참고), 분류(필수), 장소, 메모, 공유할 사람, 반복, 미리 알림 | 상 |
| REQ-EVENT-003 | 제목 | 비어 있으면 저장할 수 없다. 최대 100자. | 상 |
| REQ-EVENT-004 | 장소 | 글자로만 입력한다. 최대 100자. | 중 |
| REQ-EVENT-005 | 메모 | 자유롭게 입력한다. 최대 1,000자. | 중 |
| REQ-EVENT-006 | 일정 수정 | 참여자 누구나 일정의 공통 항목(제목, 시간, 장소, 메모, 반복)을 수정할 수 있다. 분류와 미리 알림은 개인 항목이라 본인 것만 바뀐다. | 상 |
| REQ-EVENT-007 | 내 달력에서 빼기 | 일정을 삭제하면 자신만 참여자에서 빠진다. 다른 참여자의 일정은 유지된다. 실행 전에 확인 창을 띄운다. | 상 |
| REQ-EVENT-008 | 일정 자동 삭제 | 마지막 참여자가 빠지면 일정 데이터가 서버에서 삭제된다. | 상 |
| REQ-EVENT-009 | 일정 상세 보기 | 모든 입력 항목과 참여자 목록(이름, 고유 아이디)을 보여준다. | 상 |

### 3.4 날짜와 시간 (TIME)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-TIME-001 | 시간 형태 | 일정은 하루 종일, 시작형, 마감형, 기간형 중 하나다. | 상 |
| REQ-TIME-002 | 하루 종일 | "하루 종일"을 켜면 시간 없이 시작 날짜와 종료 날짜만 입력한다. | 상 |
| REQ-TIME-003 | 시간 필수 조건 | 하루 종일이 아니면 시작 시간과 종료 시간 중 최소 하나는 입력해야 저장할 수 있다. | 상 |
| REQ-TIME-004 | 여러 날 일정 | 시작 날짜와 종료 날짜가 다른 일정을 만들 수 있다. 월간 달력에는 해당 기간 전체에 걸쳐 표시한다. | 상 |
| REQ-TIME-005 | 시간 순서 | 기간형 일정은 종료 시점이 시작 시점보다 늦어야 한다. | 상 |
| REQ-TIME-006 | 시간 단위 | 시간은 5분 단위로 선택한다. | 중 |
| REQ-TIME-007 | 마감형 표시 | 마감형 일정은 달력과 목록에서 제목 앞에 "마감" 표시를 붙인다. | 중 |

### 3.5 반복 (REPEAT)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-REPEAT-001 | 반복 종류 | 매주(일정 날짜의 요일), 매주 여러 요일, 매월 같은 날짜, 매년 같은 날짜를 지원한다. | 중 |
| REQ-REPEAT-002 | 반복 종료 | 반복 일정은 반드시 종료 날짜를 정해야 한다. | 중 |
| REQ-REPEAT-003 | 없는 날짜 처리 | 매월 반복에서 해당 날짜가 없는 달은 그 달의 마지막 날로 옮긴다(예: 31일 → 2월 28일). 매년 2월 29일 반복도 평년에는 2월 28일로 옮긴다. | 중 |
| REQ-REPEAT-004 | 반복 일정 수정·빼기 | 수정과 빼기는 반복 일정 전체에 적용된다. | 중 |

### 3.6 공유 (SHARE)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-SHARE-001 | 공유 대상 선택 | 일정 등록·수정 화면에서 자신과 연결된 사람 중 공유할 사람을 고른다. | 상 |
| REQ-SHARE-002 | 즉시 등록 | 공유된 일정은 상대의 승인 없이 상대 달력에 바로 등록된다. | 상 |
| REQ-SHARE-003 | 참여자 추가 | 참여자 누구나 자신과 연결된 사람을 참여자로 추가할 수 있다. | 상 |
| REQ-SHARE-004 | 참여자 제외 불가 | 다른 참여자를 뺄 수 없다. 각자 "내 달력에서 빼기"로만 빠진다. | 상 |
| REQ-SHARE-005 | 공유받은 일정 분류 | 공유받은 일정은 "공유받은 일정" 분류로 들어온다. 이 분류가 삭제됐다면 "그 외"로 들어온다. | 상 |
| REQ-SHARE-006 | 실시간 반영 | 일정이 수정되면 앱을 열어둔 다른 참여자의 화면에도 바로 반영된다. | 상 |

### 3.7 분류 (CAT)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-CAT-001 | 기본 분류 | 가입하면 "공유받은 일정", "개인", "직장", "가족", "그 외" 분류가 만들어진다. | 상 |
| REQ-CAT-002 | 분류 필수 | 모든 일정은 하나의 분류에 속해야 한다. | 상 |
| REQ-CAT-003 | 분류 추가·수정 | 분류 이름과 색상을 정해 추가하거나 바꿀 수 있다. 분류 이름은 중복될 수 없다. | 상 |
| REQ-CAT-004 | 분류 색상 | 정해진 색상 팔레트(10~12색) 중에서 고른다. 일정은 분류 색상으로 달력에 표시된다. | 상 |
| REQ-CAT-005 | 분류 삭제 | "그 외"를 제외한 모든 분류는 삭제할 수 있다. 삭제하면 그 안의 일정은 "그 외"로 옮겨진다. | 상 |
| REQ-CAT-006 | "그 외" 분류 | 삭제할 수 없고, 이름과 색상은 바꿀 수 있다. | 상 |
| REQ-CAT-007 | 분류 필터 | 달력에 표시할 분류를 골라서 볼 수 있다. | 상 |

### 3.8 달력 화면 (VIEW)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-VIEW-001 | 월간 달력 | 월 단위로 일정을 보여주고, 이전·다음 달로 이동할 수 있다. | 상 |
| REQ-VIEW-002 | 날짜별 목록 | 날짜를 누르면 그날의 일정 목록을 보여준다. | 상 |
| REQ-VIEW-003 | 오늘로 이동 | 버튼 하나로 오늘 날짜로 돌아온다. | 중 |

### 3.9 알림 (NOTI)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-NOTI-001 | 미리 알림 설정 | 일정마다 미리 알림을 하나 고른다. 미리 알림은 사람마다 따로 설정된다. | 중 |
| REQ-NOTI-002 | 시간 일정 알림 보기 | 없음, 30분 전, 1일 전 | 중 |
| REQ-NOTI-003 | 알림 기준 시점 | 시작형과 기간형은 시작 시간, 마감형은 종료 시간 기준으로 알린다. | 중 |
| REQ-NOTI-004 | 하루 종일 알림 보기 | 없음, 당일 오전 9시 | 중 |
| REQ-NOTI-005 | 공유받음 알림 | 누군가 나를 일정에 추가하면 알림을 받는다. | 상 |
| REQ-NOTI-006 | 수정 알림 | 참여 중인 일정을 다른 사람이 수정하면 알림을 받는다. | 상 |
| REQ-NOTI-007 | 연결 알림 | 연결 요청을 받거나 내 요청이 수락되면 알림을 받는다. | 중 |
| REQ-NOTI-008 | 본인 동작 제외 | 내가 한 동작에 대해서는 나에게 알림을 보내지 않는다. | 상 |
| REQ-NOTI-009 | 알림 목록 | 받은 알림을 최신순으로 모아 보여준다. | 중 |
| REQ-NOTI-010 | 알림 이동 | 알림을 누르면 관련 화면(일정 상세 또는 연결 화면)으로 이동한다. | 중 |
| REQ-NOTI-011 | 읽음 표시 | 안 읽은 알림은 강조하고, 알림 탭에 안 읽은 개수를 표시한다. 모두 읽음 처리를 할 수 있다. | 중 |
| REQ-NOTI-012 | 알림 보관 기간 | 90일이 지난 알림은 자동으로 삭제된다. | 중 |

### 3.10 검색 (SEARCH)

| ID | 요구사항 | 상세 내용 | 우선순위 |
|---|---|---|---|
| REQ-SEARCH-001 | 일정 검색 | 검색어로 내가 참여 중인 일정의 제목, 장소, 메모를 검색한다. | 중 |
| REQ-SEARCH-002 | 검색 범위 | 분류 필터와 관계없이 모든 분류의 일정을 검색한다. | 중 |
| REQ-SEARCH-003 | 검색 결과 정렬 | 가까운 날짜 순으로 보여준다. 반복 일정은 하나로 묶어 표시한다. | 중 |

## 4. 비기능 요구사항

| ID | 구분 | 요구사항 | 상세 내용 |
|---|---|---|---|
| NFR-001 | 플랫폼 | 지원 OS | 안드로이드. 최소 버전은 Flutter 기본 설정을 따른다. |
| NFR-002 | 언어 | 지원 언어 | 한국어만 지원한다. |
| NFR-003 | 화면 | 테마 | 라이트 모드만 지원한다. |
| NFR-004 | 오프라인 | 연결 끊김 | 마지막으로 불러온 일정을 볼 수만 있고, 등록과 수정은 막는다. 오프라인 상태임을 화면에 표시한다. |
| NFR-005 | 보안 | 비밀번호 | 8자 이상, 영문과 숫자를 모두 포함해야 한다. |
| NFR-006 | 보안 | 데이터 접근 | 일정은 참여자만, 분류와 알림 설정은 본인만 조회하고 수정할 수 있다. 서버(RLS)에서 강제한다. |
| NFR-007 | 보안 | 개인정보 | 이메일은 다른 사용자에게 노출하지 않는다. |
| NFR-008 | 시간대 | 저장 방식 | 시간은 UTC로 저장하고 기기의 시간대로 표시한다. |
| NFR-009 | 성능 | 실시간 반영 | 다른 참여자의 수정이 몇 초 안에 화면에 반영된다. |
| NFR-010 | 동시성 | 동시 수정 | 여러 사람이 동시에 수정하면 마지막에 저장한 내용이 적용된다. |

## 5. 1.0 제외 범위

- 소셜 로그인
- 매일 반복, 끝나지 않는 반복, 횟수 지정 반복
- 반복 일정의 "이번 일정만 수정"
- 주간, 일간 보기
- 수정 이력, 일정 댓글, 지도
- 외부 캘린더 불러오기
- 차단 기능
- 다크 모드, 다국어

## 6. 확인이 필요한 제안 사항

인터뷰에서 정하지 않아 일반적인 값으로 넣은 항목이다.

| 항목 | 제안값 | 관련 요구사항 |
|---|---|---|
| 이름 규칙 | 1~20자, 중복 허용, 변경 가능 | REQ-AUTH-008 |
| 제목, 장소, 메모 글자 수 | 100자, 100자, 1,000자 | REQ-EVENT-003~005 |
